## 第二种：人员类型按`公司员工`

> 这里主要是公司员工是子公司的员工，并不在我们的花名册中，但是也要统计

### 逻辑处理

用餐处理：首先是从数据源HRIS_INS_DETAIL表中：APPROVAL_TYPE = USER_CUSTOMIZATION 和 SETTING_NAME = ‘用餐申请单’ 数据。

### 场景：

用餐申请时间是选择了两段：2026-09-11到2026-09-12；2026-09-14到2026-09-19

这里需要先检查就餐地点是否是`集团总部`，就餐人员姓名是多个（可能使用中英文的逗号或者是中英文顿号去隔开），需要拆分成多人独立去计算他们分别用餐天数。这里还需要`减去节假日`，即可得到他们在集团用餐的具体天数。

（这里要注意的是：这里的申请人其实是由行政人员发起的，但是用餐人员不是他，你可以想一下，因为后边会有一些员工是长时间停餐和别的工厂的员工长时间在总部用餐的情况，可否给一个配置的处理，如果他们长时间停餐突然想用餐了，那就启用开关操作，这样也省去提单的麻烦。这样针对某些特殊人员的停餐用餐就有两个入口，平常人员就是一个入口）

## 开发编码

| 单据类型（APPROVAL_TYPE） | 值                 | 申请单据模板值（SETTING_NAME） |      |
| ------------------------- | ------------------ | ------------------------------ | ---- |
| 停餐申请单                | USER_CUSTOMIZATION | 停餐申请单                     |      |
| 用餐申请单                | USER_CUSTOMIZATION | 用餐申请单                     |      |
| 出差申请单                | EVECTION           | 出差或外出申请                 |      |
| 请假申请                  | LEAVE_ADJUST_GROUP | 请假申请（总部）               |      |



数据源：单据类型值：APPROVAL_TYPE = USER_CUSTOMIZATION 和 SETTING_NAME = ‘用餐申请单’
